lilbee runs your models and puts them to work as a search engine you can talk to. It searches your files, notes, code and saved web pages, and every answer cites its source, down to the line or page. It also crawls websites into your library, [launches your coding agents on local models](#launch-your-coding-agent-on-local-models), and gives any [MCP-aware agent](#a-reference-for-ai-agents) cited answers. Ask in plain English.

It is private. Your files, the index and your questions stay on your machine. No telemetry, no account. lilbee contacts a cloud provider only when you set its API key.

**Prefer a GUI?** The [Obsidian plugin](https://obsidian.lilbee.sh/) puts lilbee's model manager and search inside your vault, with no terminal needed.

![ask lilbee "what is lilbee in one sentence?" and get a cited answer drawn from its own README](https://raw.githubusercontent.com/tobocop2/lilbee/gh-pages/demos/what_is_lilbee.gif)

> **Tutorial reel:** every demo on this page and more, with long-form captions, at [**lilbee.sh/tutorial**](https://lilbee.sh/tutorial).

> **Beta software.** lilbee is in **active beta**. Every PyPI release is a pre-release, so `pip` needs `--pre` and `uv` needs `--prerelease=allow`. Commands and on-disk formats can change between betas. Bug reports are very welcome; that's the whole point of the beta. Latest pre-release: [lilbee on PyPI](https://pypi.org/project/lilbee/).

## Why lilbee

A small local model is fun, but limited on its own. Give it properly processed documents and a search engine over them, and it becomes genuinely powerful. Without those, it never gets past novelty.

lilbee is built for consumer hardware and for people who don't want to babysit infrastructure. It isn't another model server you point an app at; it's a local search engine with the model runner built in.

- **Install one file. Talk to your stuff.** Most ways to chat with your documents locally mean Docker, a separate model server, a database service and a browser tab. lilbee needs none of them. Point it at a folder, and local AI is useful from the first question.
- **A search engine with proof.** On MS MARCO (8.8M passages, 6,980 real queries), lilbee's general-purpose pipeline scores MRR@10 0.365. That is above ColBERT, a system trained only for that test. Few local tools publish a retrieval score for their own pipeline at all. [See the benchmark](docs/benchmarks/retrieval-msmarco.md).
- **Native speed underneath.** Models run in [llama.cpp] (C and C++). The index, the document reader, the crawler and the code parser are Rust ([LanceDB], [Xberg], [crawlberg], [tree-sitter]). [Nuitka] compiles lilbee itself into one native binary.
- **Runs on what you have.** Native executables for macOS, Linux and Windows, with Metal, Vulkan, CUDA and ROCm builds, and a build for CPUs from before 2013. One command on Homebrew, Scoop, AUR, Nix, Flatpak, Snap, npm, PyPI or Docker. [Smaller than LM Studio everywhere, and than Ollama on Windows and Linux](#one-file-the-whole-stack), and it carries the whole stack.
- **Every GPU does the work.** Chat, embedding, vision and rerank are placed together across all your cards, and indexing runs one embedder on each card. A model too big for one card [runs across several](#run-a-model-bigger-than-one-card).
- **Answers you can check.** Click a citation to open the source at the line or page. When the answer isn't in your library, lilbee says so. The [wiki](#wiki) checks every cited excerpt against the source before a page publishes.
- **Your agents, on local models.** `lilbee launch` starts a model and your coding agent, with lilbee's search connected over MCP. [Watch four agents share one model](#agents).
- **Private.** Your files, the index, the embeddings, your questions and the answers stay on your machine.

The same engine works two ways:

- **An [Encarta 99](https://en.wikipedia.org/wiki/Encarta) over your own files.** Build a library from your documents and saved web pages, then read it and ask it questions in the terminal.
- **A reference layer for code.** Point it at your project, dependencies and API docs. Your coding agent answers from what is actually there, with file:line citations, instead of guessing function names.

> **The long-term goal:** make local AI genuinely useful on hardware you already own, with no token budgets, no provider to depend on, and nothing about your files leaving your machine; the cloud's there only when you want it.

### And more

- **Know before you download.** lilbee checks a model's fit against your GPUs, and [flags a model the engine can't run](#see-when-a-model-wont-load-before-you-download-it).
- **Chunks that stand on their own.** [Prose and code are split differently](#documents-code-and-scanned-images), which is where most of the retrieval quality lives.
- **Already on Ollama or LM Studio? Keep them.** lilbee's own manager covers the same [architectures](#supported-models) they run, and [their models show up in lilbee's pickers](#already-running-ollama-or-lm-studio-keep-them).
- **Per-project libraries.** One library for everything, or [one per project](docs/usage.md#per-project-libraries).
- **Tunable.** Sane defaults, and 50+ [settings](docs/settings.md) from the TUI, MCP, HTTP, env vars or `config.toml`.
- **The demos are real.** Every GIF and reel is recorded live on real hardware, nothing staged. 100% test coverage, full typing, CI on macOS, Linux and Windows.

## One file. The whole stack.

No model server, no [vector database](#built-on), no container to stand up. One executable holds all of it:

| | |
|---|---|
| **Search engine** | hybrid search, reranking and cited answers over everything you index |
| **Model runner** | browse Hugging Face, pull a model, run it on Metal, Vulkan, CUDA or ROCm |
| **Multi-GPU fleet** | chat, embedding, vision and rerank placed across every card, behind a load-balancing router |
| **Web crawler** | save a whole docs site to your library and search it offline |
| **Document reader** | 120+ file types, OCR for scans, code split by function across 300+ languages |
| **Wiki writer** | cited, verified pages about the concepts in your library |
| **Agent server** | MCP for coding agents, plus an Anthropic- and OpenAI-style API |
| **HTTP API, TUI, CLI** | and a Python library, all from the same file |

It loads on demand. Close it and it's gone; nothing stays running.

And it is still small. Even lilbee's CUDA build stays under Ollama's, and it's the whole stack, not just a model runner.

## Install

```sh
curl -fsSL https://lilbee.sh/install.sh | sh     # macOS / Linux
irm https://lilbee.sh/install.ps1 | iex          # Windows
```

Or use your package manager:

| | |
|---|---|
| **Homebrew** | `brew tap tobocop2/lilbee && brew install lilbee` |
| **Scoop** | `scoop install git; scoop bucket add lilbee https://github.com/tobocop2/scoop-lilbee; scoop install lilbee` |
| **AUR** | `paru -S lilbee` |
| **Nix** | `nix run github:tobocop2/lilbee` |
| **npm** | `npm install -g lilbee` |
| **Docker** | `docker run --rm -v lilbee-data:/home/lilbee/data ghcr.io/tobocop2/lilbee:latest --help` |
| **Flatpak, Snap, binary** | see the [install guide](docs/install.md#every-channel) |

Then start it:

```bash
lilbee self-check    # ~90 MB download; one inference and one embedding; prints "SELF-CHECK PASSED"
lilbee               # the terminal app; pick your models on first run
```

Pick a model that fits your machine from the catalog, and you're chatting. The [usage guide](docs/usage.md) covers the rest: TUI screens, slash commands, CLI, HTTP server, MCP, env vars and `config.toml`.

The bundled builds use your GPU through Vulkan or Metal. NVIDIA and AMD cards get faster [CUDA](docs/install.md#nvidia-cuda) and [ROCm](docs/install.md#amd-rocm) builds. The [install guide](docs/install.md) also covers [older CPUs](docs/install.md#older-cpus-pre-avx2), [pip and uv](docs/install.md#pip-and-uv), and [hardware requirements](docs/install.md#hardware-requirements).

## How lilbee compares

lilbee sits between the desktop runners that get one model chatting ([Ollama](https://ollama.com), [LM Studio](https://lmstudio.ai)) and [vLLM](https://github.com/vllm-project/vllm), the server that pushes one model to many users. It places chat, embedding, vision and reranking together across the GPUs in the machine, and spreads indexing across every card.

The closest project is [AnythingLLM](https://github.com/Mintplex-Labs/anything-llm), an all-in-one app for chat with your documents. It ships as an Electron desktop app or a Docker server; lilbee is one headless executable. AnythingLLM sends telemetry unless you turn it off; lilbee sends none.

### Documents, code, and scanned images

- **Documents** (PDFs, Office files, ebooks, HTML, 120+ file types) go through [Xberg] with heading-aware chunking, so each chunk keeps its section.
- **Code** goes through [tree-sitter] across [300+ languages](https://github.com/Goldziher/tree-sitter-language-pack), so chunks are functions and classes, not arbitrary line ranges.
- **Scans and photos** go through OCR in 100+ languages: Tesseract for plain text (set `LILBEE_OCR_LANGUAGE`, for example `eng+deu`), or a local or remote vision model that keeps tables and layout as markdown.

Search returns pieces that make sense on their own, not fragments cut through an argument or a function signature.

### Tested GPUs and backends

Every backend reports hardware differently, so lilbee checks each one on real silicon: CUDA from an RTX 3090 up to an H200 and eight A100s at once, Vulkan on NVIDIA and Intel, ROCm on an AMD Instinct MI300X, Metal on Apple silicon, and a CPU-only host. [Tested GPUs](docs/tested-gpus.md) lists every machine and what each run settled. Send captures from hardware the table does not list.

## Agents

lilbee serves your coding agents two ways, both local: it runs the models they talk to, and it answers their searches with cited snippets from your library.

### Launch your coding agent on local models

One command sets up your agent on lilbee's local models:

```bash
lilbee launch opencode    # or: hermes, pi, claude
```

Each launch warms a model and opens the agent pointed at it. No API keys, no provider setup, and nothing leaves your machine, except a check of any provider API key you have set. [Agent models](docs/agent-models.md) lists the models verified for tool calling, and how the QA harness measures it.

- **opencode and hermes:** lilbee registers itself as a provider and an MCP server in the agent's own config, and leaves the rest of your setup intact.
- **Claude Code:** lilbee serves an Anthropic-style API and points the session at it through the environment. Claude Code's settings stay untouched.
- **pi:** lilbee writes nothing into pi's config. It starts pi with lilbee's pi extension and the `lilbee-mcp` skill for that session only. Tested with pi 1.5.0; pi needs Node 22.19 or newer.

One model serves as many agents as you want to run. Here, four agents work at once on one local model, each in its own worktree, reading and searching this repository through lilbee.

### A reference for AI agents

Feed lilbee your project docs, dependency source and API docs. Over MCP, your agent reads the actual code, cites file and line, and says when the answer isn't in your library. This works with cloud agents too: only the query and the returned snippets reach the model.

The [`lilbee-mcp` skill](plugins/lilbee/skills/lilbee-mcp/SKILL.md) is the single entry point. It teaches the search, cite and long-operation workflow, over MCP or the `lilbee --json` CLI, and points to drop-in `AGENTS.md` and worker-subagent starters under [`examples/agent-integration/`](examples/agent-integration/). Agents can also tune lilbee's settings on the fly with `lilbee_settings_set`. The [install table](docs/usage.md#install-in-your-agent) has one command each for Claude Code, opencode, pi and Hermes, and the plain MCP form for any other agent.

## Run a model bigger than one card

When a model won't fit on one GPU, lilbee spreads it across the ones you have. It sizes each role's memory with gguf-parser, keeps headroom on every card, and tensor-splits the chat model across the fewest GPUs that fit. The embedder, reranker and vision models sit alongside it behind a load-balancing router. It's automatic. Here a 70B runs across three consumer cards and answers a mechanic's question from a car manual, with the page cited.

To place it by hand, the placement editor pins each role to the cards you pick and previews the fit before anything loads, and applies it live. If a layout can't fit, it tells you the exact shortfall.

## Wiki

lilbee reads your library and writes a wiki about it: one page per concept or entity, not per document. A subject that recurs earns its own page, cited from the source that mentions it most and cross-linked with `[[wiki link]]`; synthesis pages cover what spans several sources. Every section is checked against the source text before it publishes, and lower-confidence pages wait in a `drafts/` queue for review. Open a page that doesn't exist yet and lilbee writes it from your sources, then links it into the rest.

## Built on

lilbee stands on a stack of established open-source projects, all bundled into one install:

lilbee stands on a stack of established open-source projects, all bundled into one install:

- [Xberg] parses 120+ file types with heading-aware chunking.
- [llama.cpp] is the local model runtime: lilbee bundles its `llama-server` and starts it for you, so every chat, embedding, vision, and reranker call goes through it. [llama-swap] keeps a server per role resident together behind one endpoint, and [gguf-parser] estimates each model's memory footprint so lilbee loads what fits. Without llama.cpp there is no lilbee.
- [Hugging Face Hub] (via [huggingface_hub]) hosts the model catalog and handles every download. Search, browse, and pull all route through it.
- [liter-llm] connects to hosted and local model providers: OpenAI, Anthropic, Gemini, Ollama, LM Studio and others.
- [LanceDB] is the embedded vector store.
- [tree-sitter] (via [tree-sitter-language-pack]) chunks code across 300+ languages.
- [crawlberg] crawls the web, and [Playwright] installs its headless Chromium; [Tesseract] is the OCR fallback when no vision model is set.
- [Textual] draws the terminal; [Litestar] runs the HTTP server.
- [MCP Python SDK] is the agent surface; [Typer] is the CLI; [Pydantic] is the config + validation backbone.
- [Nuitka] compiles the whole thing into the standalone single-file binary, bundling its own Python runtime so there is nothing to install and nothing to compile.

## FAQ

**Does my data leave my machine?** No. Your files stay on disk and search runs locally. A cloud model is used only when you pick one.

**Will a model fit my GPU?** lilbee reads the GGUF file and your devices and estimates fit before you download, and splits large models across multiple GPUs. More at [lilbee.sh/gpu](https://lilbee.sh/gpu/).

**Can my coding agent use it?** Yes, over MCP. The agent reads your real code and docs before answering, cited to the file and line. More at [lilbee.sh/mcp](https://lilbee.sh/mcp/).
